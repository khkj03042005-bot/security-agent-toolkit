## [Network-014] 정규표현식 · 탐지 룰

### 한 일
- 쉼표 없는 서버 로그 `raw_logs.txt`(20줄)를 정규표현식으로 정규화하는 `agent_core/normalize_logs.py` 작성
- 패턴에 맞는 줄은 `normalized_logs.json`, 안 맞는 줄은 `unmatched_logs.txt` 로 저장
- 정규화한 기록으로 탐지 룰 두 개 작성
  - 룰 ① 브루트포스: 한 계정의 로그인 실패가 3회 이상
  - 룰 ② 의심 IP: 한 IP 에서 계정 2개 이상 시도

### 확인한 결과
- `python normalize_logs.py` → 정규화 16건 / 안 맞음 4건
- `unmatched_logs.txt`: session closed 3줄 + invalid user 1줄
- 계정별 실패 횟수: admin 4회, 나머지 계정은 각 1회
- [룰 1] 확인 필요: admin — 실패 4회
- [룰 2] 의심 IP: 185.220.101.34 — 계정 4개 시도
- `split()` 으로 6번 칸을 꺼내면 `invalid`, `10.1.2.34` 처럼 계정이 아닌 값이 에러 없이 섞여 나옴

### 새로 알게 된 점
- `split()` 은 칸이 밀려도 에러 없이 조용히 틀린 값을 준다. 정규식은 앞뒤 글자(`for`, `from`)로 자리를 고정해서, 모양이 다른 줄은 안 맞는 줄로 골라낸다
- `(?P<이름>...)` 으로 괄호에 이름을 붙이면 `.groupdict()` 한 번으로 로그 한 줄이 딕셔너리 한 개가 된다
- `re.search` 는 못 찾으면 `None` 이라 `if m:` 확인이 필요하고, `re.findall` 은 빈 리스트 `[]` 를 준다
- 안 맞는 줄을 버리지 않고 따로 저장해야 패턴이 틀렸는지, 원래 다른 종류의 로그인지 나중에 판단할 수 있다
- 같은 기록이라도 계정 기준으로 세면 브루트포스가, IP 기준으로 모으면 여러 계정을 두드리는 IP 가 보인다

### 임계값을 정한 근거
- 임계값 1 → 경보 7건 / 2 → 1건 / 3 → 1건
- 3 으로 정했다. 한두 번 틀리는 건 흔한 실수라 1·2 는 헛경보가 많고, 3번 이상 실패는 정상 사용에서 드물기 때문이다

### 찾아본 것과 배운 것의 차이
- 비정형 로그 → 찾아본 것: 정해진 칸 없이 자유로운 글 형태의 기록. 배운 것: 단순히 '형식이 없다'가 아니라, 줄마다 단어 수가 달라서 split 칸 번호가 밀리고 그래도 에러가 안 난다는 게 진짜 위험이었다. (invalid user 줄에서 계정 자리에 invalid 가 들어옴)
- 정규표현식 → 찾아본 것: 문자열 패턴을 찾는 표기법. 배운 것: 모양만 적으면 엉뚱한 곳이 잡힌다. [\d.]+ 만 쓰면 날짜 2026 이 먼저 잡혀서, 앞에 from 같은 글자를 붙여 자리를 못박아야 했다.
- 그룹 / named group → 찾아본 것: 괄호로 묶어 일부를 꺼내고, 이름을 붙이면 번호 대신 이름으로 부른다. 배운 것: 이름을 붙이면 groupdict() 한 번에 딕셔너리가 돼서 바로 JSON 으로 저장할 수 있었다. 편해지는 정도가 아니라 정규화 결과 그 자체가 된다.
- 브루트포스 / 임계값 →  찾아본 것: 비밀번호를 반복 대입하는 공격, 경보 기준이 되는 숫자. 배운 것: 같은 기록을 계정 기준으로 세면 브루트포스가, IP 기준으로 모으면 여러 계정을 두드리는 공격이 보였다. 임계값 2와 3은 우리 로그에서 결과가 같아서, 숫자는 정답이 아니라 데이터를 보고 사람이 정하는 것이었다.
